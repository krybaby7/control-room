# Concise user messages first

The owner approved local selection that prioritizes recent concise user messages before inference. This remains one finite, read-only GPT-6.1 Sol call with tools disabled. No AI triage round, new provider, history access expansion or token-free inference claim is added.

Within each provider reader's existing latest matching conversation and last-six-message window, sanitize whole messages before any classification or clipping. Rank user messages of at most 800 characters with ordinary prose formatting ahead of long prompts and code/template blocks. Formatting is a heuristic, not evidence of personal authorship or pasting. Keep selected user messages complete and in chronological order within the existing 2,000-character provider budget. Do not fill unused space just to reach the cap.

When a selected short instruction appears context dependent (for example, "yes, do option two"), include at most 600 characters of its nearest preceding safe assistant answer, within the same total budget. Plain standalone user requests do not bring in assistant answers. If no concise user message qualifies, retain at most 1,000 characters from the latest safe user message as a disclosed fallback. Preserve beginning and end when shortening a message. Do not send assistant-only history; label that source deferred. All existing secret/path/tool/reasoning, project identity, file-link, discovery and time bounds remain enforced.

New reports explain that concise user inputs were prioritized, that length/format do not establish authorship, and that omitted material remains partial coverage. Source `deferred` means eligible history existed but no safe user input was selected; it is distinct from unavailable or not found.
