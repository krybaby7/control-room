## What changed

- **Workspace:** canonical `personalRepositoryKeys` has at most four unique keys. Older `personalRepositoryKey` becomes a singleton list on read; absent associations become empty lists. Duplicate ownership is rejected across active and archived projects. Empty generated lists are omitted by compact storage with exact byte-accounting parity. Framing, IDs, export and restore remain intact.
- **Admission:** new briefing jobs carry an ordered folder list and project framing projected from saved workspace state. Owner requests cannot supply either payload. Every selected folder must be registered; another project's folder cannot be admitted. Existing revision fencing covers the projection. Completion must match all admitted folder identities, project name, provider and framing coverage. An immutable completed report remains saveable if project membership changes after admission.
- **Automatic refresh:** keep-current policies are per project; device polls reproject their membership from current saved projects, under a workspace revision fence. Archived, missing or empty projects disable their policy. Temporarily unavailable folder registration hides automatic dispatch while retaining the preference. A combined digest of sorted folder-key/fingerprint pairs changes when any folder's bounded work evidence or membership changes.
- **Evidence:** existing per-folder readers retain local branches, fetched cloud branches, pull requests, uncommitted work, partial local chat excerpts, original owner turns and repository cloud handoffs. The project collector labels sections and sessions by folder, orders owner sessions globally newest first with sessions since the prior briefing first, and trims the oldest retained material across folders. Coverage is recomputed after trimming. Every per-folder reader limit is retained. The shared merged pack remains within **160,000 bytes** and the prompt within **240,000 bytes**; synthetic two-folder UTF-8 fixtures fit through global trimming, so no input-byte ceiling increase was needed. Per-folder coverage remains explicit even when a folder has no retained turns.
- **Contract:** version **4** requires all folder identities and per-folder local/cloud/chat/owner-turn/fetch coverage. Areas can name a folder; intentions can carry folder-specific `{repositoryKey, ref}` evidence references as well as historical strings. Unknown keys, duplicates and identity/coverage mismatches reject. Frozen v1/v2/v3 schemas project purely to v4 with their original single-folder coverage, without inventing framing or cloud provenance. Report characters rise from 26,200 to **32,200** for identities/coverage, with the existing **55,000-byte** delivery ceiling unchanged. Previous ledgers preserve folder attribution.
- **Ledger and recovery:** one active saved briefing per project; refreshing an old folder-specific head consolidates other active heads atomically while retaining their history. Reads show the newest project ledger. Companion previous-ledger lookup accepts historical single-folder backups for the project, including on the first multi-folder run. Per-request private backups retain all folder identities and framing coverage. Delivery/retry uses the original request without a second model call.
- **Prompt:** the folders are parts of one project with one aim, cross-folder map and intention ledger. Name a folder where it matters, retain spanning intentions as one row, and distinguish one folder's evidence from another's. Framing remains a reference rather than an intention source; task-plan inclusion stays off by default.
- **Screens:** both creation dialogs put optional “What this project is and why” first. Registered folders can create a project or join an existing one without inference. Historical analysis destinations do not imply saved folder ownership. The project page and briefing card list folders with an add action; areas show small folder tags, the basis fold lists coverage by folder and the new-work flag names changed/newly added folders.
