# Simple UI plan

**Goal:** Make Control Room simple, calm and built around the AI project briefing. Every existing capability stays reachable; only its place changes.

**Scope:** UI and navigation only, on `feat/simple-ui` from `main` `7f77a81`. No change to data contracts or stored formats (`shared/project-briefing.mjs`, `shared/personal-repository.mjs`, the workspace schema, migrations, API routes and payloads) or companion code. No merge, no Site publication, no GitHub settings change, no other branch touched. Synthetic fixture data only.

**Workers:** `AGENTS.md` asks for GPT-6.1 Sol implementation and review workers. This runtime's agent tool offers only Claude models, so it cannot select `gpt-6.1-sol`. The owner authorized direct implementation and review for this task in that case; the verification note records it.

## The owner's jobs, in order

1. See where each project stands and what it is aiming at.
2. See what needs me.
3. Know the next step.
4. Get a fresh briefing in one click.
5. Move between projects quickly.

Every first-level screen answers one or more of these jobs. Anything that does not is moved behind **Advanced**.

## Navigation

Four items, the same on PC, tablet and phone:

| Item | Answers | Notes |
|---|---|---|
| **Home** | jobs 1, 3, 4, 5 | The first screen. One calm card per active project. |
| **Projects** | job 5 | A plain list of projects; each opens its project page. |
| **Needs you** | job 2 | Everything waiting on the owner, in one list, grouped by project. |
| **Advanced** | — | One page that lists every detailed tool with a one-line plain description. |

"Quick capture" stays as a small secondary button (sidebar on PC, Home header everywhere) because it is an action, not a place. The account menu and sign-out stay where they are.

Every existing address keeps working: `/?view=lanes`, `/?view=today`, `/?view=weekly`, links to projects, milestones, tasks, captures, review citations and evidence subjects open the same screens as before. When an Advanced tool is open, **Advanced** is highlighted and a "Back to Advanced" link sits above the tool. A plain address (`/`) now opens Home instead of Project lanes.

## Screen map

### Home (first screen)

- Heading "Home", one line of explanation, a quiet "Capture an idea" button.
- One card per active project, built from its latest briefing:
  - project name (opens the project page) and a short plain status ("On track", "At risk", …) when a briefing exists;
  - **The aim right now** (falls back to the owner-written goal, labelled as such, when there is no briefing yet);
  - **Where we're at** in two or three lines (the briefing's "where we left off");
  - **Needs you** (at most three lines from the briefing);
  - **Next step** (the briefing's first next step; otherwise the plan's suggested next task);
  - one primary action: **Brief this project** or **Refresh briefing**, with its plain-language disabled reason next to it (`lib/project-action-reasons.ts`), and a quiet "Open project" link;
  - a single calm line while a briefing is being written, when it failed, or when new work arrived since the last briefing.
- No status-light strip, meters, counters, token totals, agent runs or mission log.
- Performance: the Home frame (heading, cards with name and goal, Capture) is in the startup code; the briefing part of each card loads after first paint through the existing deferred-panel pattern, with the plain cards as its loading state. Project lanes leave the startup code (they move behind Advanced), so the startup bundle gets smaller, not larger. The "controlled browser performance" check is rewritten to measure Home with the same 3,000 ms budget and the same five cold mobile loads, and its navigation check visits the new screens plus the same Agents, Runtime and Sources tools.

### Project page

In this order:

1. Back to Projects; project name; archived notice when archived.
2. **Briefing**: status, aim right now, where it stands (where we left off, how it fits the bigger picture), **your intentions and what became of them**, **needs you**, **next steps**, and the primary **Brief this project / Refresh briefing** action with its disabled reason. Folded: briefing settings (assistant, keep current), project map and plan changes, what was tried, done and not yet done, how the briefing was put together (evidence, coverage, references).
3. **Folders on your PC**: unchanged component — add, remove and brief work exactly as today.
4. **Plan: milestones and tasks**, folded by default: areas, dated baseline, milestones, tasks with their filters, and "change many tasks at once". Bulk task actions load only when the fold is opened.
5. **About this project**: the goal, the framing (first lines), **Edit project** (goal and framing), archive or restore, and folded technical links (review context, technical analysis).

### Projects

Heading, one primary action **New project**, an Active / Archived / All filter, and one plain row per project (name, goal, "Open"). Archived projects stay listed under the filter.

### Needs you

Grouped list built from the same saved records the old Today "Needs you" panel and attention model used, without the eight-item cap:

- from the latest briefings ("Raised by the project briefing");
- decisions waiting on you: tasks in review, agent job proposals waiting for approval, runs that need reconciliation;
- overdue work;
- captured ideas waiting to be sorted;
- tasks pinned in an earlier week and still open.

Each row opens the task, project, inbox or Agents tool it came from. A footer link opens the full planning attention queue under Advanced.

### Advanced

One page, grouped, each entry a button with a one-line plain description:

- **Plan and review:** Project lanes, Mission control (the old Today page), Weekly planning, Search, Attention, Inbox, Change many tasks at once.
- **Records:** History, Evidence & decisions, Sources, export and restore.
- **Your PC and assistants:** Repositories (folders on this PC, technical analysis, Codex Cloud import), Briefs & automations, Runtime, Agents.
- **Connection details:** live-update method, last saved and last refreshed times (shown inline).

Every Advanced tool keeps its current content and behaviour.
